예외                     배수 10 이상이면 조회수를 보지 않고 통과시킨다.

게이트를 낮추지 않는다. 통과가 적으면 적은 대로 둔다.

게이트판정 = 통과 / 미달 / 판정불가(지표없음)
게이트근거 = 숫자를 그대로 적는다.

■ 11. 커밋과 배포

계정 20개마다 커밋하고 push 한다.
  메시지는 "채굴 n/343 · 채택 n건". 커밋 메시지는 -F 로 파일에서 읽힌다.

배포는 시간 기준으로 한다.
  마지막 배포로부터 2시간이 지났고 그 사이 커밋이 하나라도 있으면  npm run deploy
  새 데이터가 없으면 배포하지 않는다.
  배포 시각을 PROGRESS.md에 남긴다. 이 기록이 다음 판단의 근거다.
  하루 상한 100건에 2시간 주기는 12건이라 여유가 있다.

배포는 계정 채굴이 끝난 직후에만 한다. CSV를 쓰는 중간에 하지 않는다.
배포가 실패하면 두 번까지 다시 하고, 그래도 안 되면 PROGRESS.md에 적고 채굴을 계속한다.
배포 실패로 채굴을 멈추지 않는다. 배포는 부수 작업이다.

배포 명령은 npm run deploy 뿐이다. 다른 명령을 만들지 않는다.
  저장소 루트에서 vercel --prod 를 치면 Output Directory 기본값이 public 이라
  index.html 없는 데이터 폴더만 올라가 사이트가 깨진다.
  vercel deploy dist --prod 를 치면 dist 라는 이름의 새 프로젝트가 생긴다.
  둘 다 실제로 일어난 사고다. scripts\deploy.mjs 가 이걸 막아준다.
GitHub 연동이 없어서 push 만으로는 사이트가 안 바뀐다.
